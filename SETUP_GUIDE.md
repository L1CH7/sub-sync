# Руководство по настройке мульти-подписок, Clash Verge Rev и каскадов в `sub-sync`

## 1. Базовая настройка через TUI (первая подписка)

Интерактивное меню (`uv run main.py`) по-прежнему отвечает только за первичную настройку доступа с ПК (`target_url`, `headers`, автозапуск службы `vpn-spoof.service`). Все расширенные параметры добавляются вручную в `data/config.json` (образец — [config.example.json](file:///home/vaivanov/dev/tools/vpn-spoof-proj/sub-sync/data/config.example.json)) и не ломают TUI.

---

## 2. Доступные HTTP-маршруты

После запуска прокси-службы доступны следующие адреса (на примере порта `54321`):

| Маршрут | Что возвращает | Клиент |
| :--- | :--- | :--- |
| `http://127.0.0.1:54321/sub` | Автоопределение по `User-Agent` (для Clash — `merged/clash`, для остальных — `1/xray`) | Любой |
| `http://127.0.0.1:54321/sub/1/xray` | Оригинальный формат подписки №1 + инлайновые мосты `xray_chains` | Happ / v2RayTun |
| `http://127.0.0.1:54321/sub/1/clash` | Только подписка №1 в формате Clash/Mihomo с группами и мостами | Clash Verge Rev |
| `http://127.0.0.1:54321/sub/2/clash` | Только подписка №2 в формате Clash/Mihomo | Clash Verge Rev |
| `http://127.0.0.1:54321/sub/merged/clash` | Объединение всех подписок + учёт квот + каскады `dialer-proxy` | Clash Verge Rev |
| `http://127.0.0.1:54321/sub/merged/xray` | Объединение всех подписок в JSON Xray | Happ |
| `http://127.0.0.1:54321/sub/merged/raw` | Base64-список ссылок `vless://` и `hysteria2://` | v2rayNG / Shadowrocket |
| `http://127.0.0.1:54321/api/status` | JSON-статус кэша, возраст обновлений и квоты по каждой подписке | Мониторинг |

К любому маршруту подписки можно дописать `?refresh=1` для принудительного сброса кэша и перекачки данных с сервера.

## 3. Добавление второй подписки (например, для белых списков)

Откройте `data/config.json` и добавьте секцию `extra_subscriptions`:

```json
{
  "listen_port": 54321,
  "label": "main",
  "target_url": "https://primary-provider.example/sub/xxx",
  "headers": { ... },
  "extra_subscriptions": [
    {
      "id": "2",
      "label": "WL",
      "target_url": "https://whitelist-provider.example/sub/yyy",
      "headers": {
        "User-Agent": "Happ/4.14.0/ios/...",
        "X-HWID": "..."
      }
    }
  ]
}
```

* Если у второй подписки не указывать `headers`, будут автоматически использованы заголовки основной подписки.
* При обращении к `/sub/merged/clash` каждый узел получит префикс `[main]` / `[WL]`, а в начало списка (при `show_limits_in_merged: true`) добавятся информационные строки с остатком трафика и датой окончания из заголовка `Subscription-Userinfo` каждой подписки.

## 4. Настройка групп и каскадов в `Clash Verge Rev`

Вся логика группировки задаётся в секции `clash` файла `data/config.json` через регулярные выражения:

* `entry_subscription_ids`: список `id` подписок, чьи узлы сразу считаются кандидатами входа на Шаге 1 (например `["2"]`).
* `entry_match`: регулярное выражение для отбора входных узлов (например, российские серверы из основной подписки).
* `groups`: массив пользовательских групп вида `{"name": "🇺🇸 США", "match": "🇺🇸|USA", "bridge": true}`. Для каждой группы с `"bridge": true` создаётся как прямой список, так и каскадная версия `🌉 🇺🇸 США`, идущая через `✈️ 1. Вход (Шаг 1)`.
* `rules`: список правил Clash (по умолчанию только `MATCH,🛡️ Режим`).

### Как пользоваться в интерфейсе `Clash Verge Rev`:
1. В разделе **Profiles** добавьте адрес `http://127.0.0.1:54321/sub/merged/clash` (или `/sub/1/clash` для одной подписки).
2. Во вкладке **Proxies**:
   * В группе **`✈️ 1. Вход (Шаг 1)`** оставьте **`⚡ Авто · Вход`** (сам выберет быстрый живой вход РФ) или выберите нужный входной сервер вручную, либо `DIRECT` для выхода без моста.
   * В группе **`🛡️ Режим`** выберите нужную страну/группу (например, `🌉 🇺🇸 США` для работы через мост или `🇺🇸 США` напрямую), а внутри группы кликните конкретный сервер.

## 5. Инлайновые каскады для `Happ` (`xray_chains`)

Если вы продолжаете использовать клиент `Happ`, в `data/config.json` можно описать готовые связки:

```json
"xray_chains": [
  {
    "name": "🌉 МСК gRPC ➔ США #1",
    "via": "Moscow #1.*GRPC",
    "to": "USA #1"
  }
]
```

Генератор сам найдёт указанные узлы по регулярным выражениям, снимет конфликтующую фрагментацию `finalmask` на каскадных звеньях, свяжет их через `dialerProxy` и добавит готовые пункты в конец списка серверов `Happ`.

## 6. Кэширование, ретраи и изолированное тестирование

* **Параметры кэша (`cache`):**
  * `ttl_sec`: срок актуальности кэша в секундах (по умолчанию `1800`). Пока кэш свежий, ответ отдаётся мгновенно без ожидания внешнего сервера.
  * `timeout_sec`: таймаут одной попытки запроса к провайдеру (по умолчанию `4.0` с — укладывается в 9-секундный лимит Happ).
  * `retries`: число попыток при холодном старте или фоновом обновлении (по умолчанию `3`).
  * Если кэш устарел, но внешний сервер не успел ответить за быстрый таймаут — клиенту мгновенно отдаётся последний рабочий кэш (`X-SubSync-Cache: stale-cache`), а в фоне запускаются повторные попытки для обновления кэша к следующему обращению.

* **Тестовый запуск на отдельном порту и конфиге (без влияния на живую службу):**
  ```bash
  uv run main.py proxy --port 54322 --config /var/tmp/scratch/test_config.json
  ```

## 7. Лёгкая диагностика ТСПУ / DPI (`check`)

Встроенный модуль [dpi_check.py](file:///home/vaivanov/dev/tools/vpn-spoof-proj/sub-sync/src/vpn_spoof/dpi_check.py) не требует дополнительных библиотек, умеет автоматически обходить активный TUN-интерфейс через физический адаптер и скачивает внешний список `tcp16.json` только локально в системный кэш (`~/.cache/subsync/diag/` или `%LOCALAPPDATA%\subsync\diag\`), не создавая мусорных файлов в репозитории.

* **Из меню TUI:** пункт `[5] Проверка ТСПУ / DPI (подписка, DNS, каскад)`.
* **Из командной строки:**
  ```bash
  uv run main.py check                                # Узлы подписки с авто-обходом TUN
  uv run main.py check --host example.com:443         # Конкретный хост
  uv run main.py check --socks 127.0.0.1:7897         # Проверка через Clash / Xray SOCKS5
  uv run main.py check --cdn                          # Срез TCP 16-20KB по базе CDN
  SUBSYNC_LIVE_DPI=1 uv run python -m unittest -v     # Автотесты + живая проверка сети
  ```
